# 批量入库

运行 `npm start`，打开目录里的「批量入库」。Node 服务会自动发现可入库的索引目录，网页和 agent 都能在同一个本机服务上上传文件、编辑草稿、校验和发布。

[查看 Agent 接入说明](../apps/reviewer/agent.md)。服务运行时可直接读取 `/agent.md`。从 `GET /api/v1/ingest-batches` 获取实际启用的项目和数据集。

可一次选择多个文件或整个文件夹。界面按文件名和相对目录建议归属，明确匹配的空字段会自动填写，已有选择会保留。到「待确认」检查剩余条目，预览后校验并发布。所有本机客户端共用草稿箱，也可以通过草稿链接打开同一份计划。

草稿里可以删除错传的文件或丢弃整批。删除模型会移除对应版本，其附件仍可重新分配。删除后需要重新校验。系统只回收已无草稿或发布记录引用的文件。

从模型详情点「追加版本」可以给现有模型上传新 GLB 和附件。发布后新版本出现在原模型下，原版本的投票、评论和选配仍能按原版本查找。用户自己的 agent 可以在每个版本的 `tags` 提交标签，发布后进入目录搜索和筛选。

模型和动画使用自包含 GLB，外置贴图绑定到材质槽的底色通道，使用 PNG 或 JPG。入库保留原始文件，网页使用轻量预览，选配导出读取原件。图片处理需要 Python 3 和 Pillow（9.1+），见[本地目录导入](LOCAL-DIRECTORY-IMPORT.md)。

## 本机数据

默认数据写入用户目录下的 `.assets-platform`，不同的程序目录分别存放。可用 `ASSETS_STATE_DIR` 指定目录。如果原来通过 `ASSETS_INGEST_CONFIG` 启动，请继续使用原配置，原有草稿、文件和发布记录会从原状态目录读取。配置里的 `stateDir`、`projects` 仍生效。

一个状态目录由一个 Node 进程写入。每批最多 48 个文件、192 MiB、20 个模型版本和 80 个附件关联。服务最多保留 256 个批次和 2 GiB 文件。服务仅监听本机 `127.0.0.1`。
